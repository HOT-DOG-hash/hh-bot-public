# Partner Integrations — API Contracts (P2.2.1)

Документ описывает требования по АPI, квотам, SLA и идемпотентности для провайдеров
hh.ru, Habr Career и generic marketplace. Все значения согласованы с командами
интеграций и служат источником правды для реализации ingest сервисов.

## 1. Общие требования
- **Формат**: HTTPS JSON, UTF-8, timestamps в ISO8601 (UTC).
- **Security**: TLS 1.2+. Все запросы подписаны вендорскими токенами
  (см. разделы ниже). Хранение секретов в Vault (`secret/integrations/<partner>`).
- **Headers**: `X-Request-Id` (UUID v4) обязателен для трассировки,
  `User-Agent: hh-bot-integrations/<version>`.
- **Idempotency**: используем `Idempotency-Key` для write эндпоинтов (см. таблицы)
  + `external_id` из payload. Ответы кэширутся на 24 часа.
- **429 policy**: exponential backoff (1s → 60s), максимум 6 попыток.
- **5xx policy**: retry по backoff до 3х попыток, после чего тикет в очередь интеграций.
- **SLA**: 99.5% доступности на окнах 30 дней, средняя задержка ответа ≤ 1.5 сек.
- **Logging**: каждый запрос/ответ сохраняется в `integration/logs/<partner>/YYYY/MM/DD/`.

## 2. hh.ru API
| Aspect | Details |
| --- | --- |
| Auth | OAuth 2.0 client credentials. Scope: `vacancies:read`, `companies:read`. Token TTL 1 час, обновление на t-5 мин. |
| Base URL | `https://api.hh.ru/v2/auto-campaigns/{tenant}` |
| Rate Limit | 900 req/15 min. Хедеры: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`. |
| Idempotency | Header `Idempotency-Key`; рекомендуемый ключ `external_id + ":" + updated_at`. Повторный ответ — HTTP 200 + `X-Idempotent-Replay: true`. |
| SLA | `p95 latency ≤ 1200 ms`, доступность ≥ 99.7%/30d. |
| Errors | 4xx: validation (422) с полями `code`, `field`, `message`. 429: `code="RATE_LIMIT"`, `retry_after`. 5xx: `code="UPSTREAM_ERROR"`, логируем `correlation_id`. |
| Retries | 429 → backoff 10s, 30s, 60s; 5xx → 5s, 15s, abort. 4xx не повторяем. |
| Pagination | `page`, `per_page` (≤100). |

### 2.1 Эндпоинты hh.ru
| Endpoint | Method | Notes |
| --- | --- | --- |
| `/vacancies` | GET | Параметры: `updated_from`, `updated_to` (`UTC`). Фильтры по `status`. |
| `/vacancies/{id}` | GET | Детализация with company block. |
| `/vacancies/{id}/status` | POST | Body `{status: "active|inactive"}`. Требует Idempotency-Key. |
| `/companies/{id}` | GET | Нормализация компаний. |

## 3. Habr Career API
| Aspect | Details |
| --- | --- |
| Auth | Header `X-Api-Key: <token>` (хранится в Vault). |
| Base URL | `https://career.habr.com/api/v2` |
| Rate Limit | 600 req/10 min. В ответе header `Retry-After` при превышении. |
| Idempotency | В POST/PUT обязательный header `X-Request-Digest` = SHA256(payload + secret). |
| SLA | 99.2%/30d, p95 latency ≤ 1500 ms. |
| Errors | 400/422 → `errors:[{code, field, message}]`; 409 при конфликте idempotency. |
| Retries | 429: backoff 5, 15, 45 сек. 5xx: 10, 30 сек. |
| Pagination | Cursor-based (`next_cursor`). |

### 3.1 Эндпоинты Habr Career
| Endpoint | Method | Notes |
| --- | --- | --- |
| `/vacancies/export` | POST | Body `{from, to, cursor}`. Возвращает batch (≤1k записей) + `next_cursor`. |
| `/vacancies/{id}` | GET | Расширенное описание. |
| `/companies` | GET | Пагинация по 100 записей. Используется для нормализации работодателей. |
| `/webhooks/vacancies` | POST | (опционально) realtime уведомления о деактивации. Требует подпись HMAC. |

## 4. Generic Partner Template
| Aspect | Details |
| --- | --- |
| Auth | Header `Authorization: HMAC <key_id>:<signature>`. Signature = `hex(HMAC_SHA256(secret, method + path + timestamp + body))`. |
| Rate Limit | Конфигурируется; по умолчанию 300 req/5 min. Макс burst: 30 req. |
| SLA | ≥ 98.5%/30d, latency ≤ 2s. |
| Idempotency | Требуем поле `external_id` + header `Idempotency-Key`. Сервер должен возвращать HTTP 200/409 с ссылкой на исходную запись. |
| Retries | 429: 15, 30, 60 сек; 5xx: 5, 15, 45 сек. |
| Errors | JSON `{code, reason, details}`; зарезервированные коды: `AUTH_FAILED`, `VALIDATION`, `RATE_LIMIT`, `SERVER_ERROR`. |
| Monitoring | Провайдер обязан отдавать `/health` (liveness) и `/metrics` (Prometheus format) для SLA audits. |

### 4.1 Обязательные поля payload
- `external_id` (string, ≤128)
- `title` (string)
- `description` (markdown/plain)
- `company` (object: `name`, `external_id?`)
- `salary` (object: `min`, `max`, `currency`)
- `location` (object: `country`, `region?`, `city?`, `lat?`, `lon?`)
- `employment_type` (`full_time|part_time|contract|remote`)
- `posted_at`, `updated_at`
- `url`

### 4.2 События lifecycle
| Event | Payload | Requirements |
| --- | --- | --- |
| `vacancy.created` | полное описание | доставляется в течение 5 мин; повтор до ack 200. |
| `vacancy.updated` | diff или full | содержит `changes[]`. |
| `vacancy.closed` | `{external_id, closed_at}` | обязательный параметр `reason`. |

## 5. Ошибки и remediation
| Code | Meaning | Client Action |
| --- | --- | --- |
| `RATE_LIMIT` | достигнут лимит | уважаем `Retry-After`, backoff. |
| `AUTH_FAILED` | токен/подпись невалидные | перевыпустить секрет, уведомить партнёра. |
| `VALIDATION` | payload не прошёл проверки | логируем, уведомляем провайдера, ручная правка. |
| `IDEMPOTENT_REPLAY` | повтор запроса с другим payload | сравнить `hash_payload`, открыть тикет. |
| `SERVER_ERROR` | 5xx на стороне партнёра | повторяем по политике, эскалируем при >3 подряд. |

## 6. SLA & Reporting
- **Monitoring**: экспортируем метрики `partner_ingest_total`, `partner_ingest_errors_total`,
  `partner_quota_remaining`, `partner_webhook_lag_seconds`.
- **SLA Review**: ежемесячный отчёт → таблица в Confluence + выгрузка метрик.
- **Escalation**: нарушение SLA > 4 часа → уведомление Partner Success и создание Jira ticket.

## 7. Контроль версий
- Изменение контракта → семантическая версия в `_contracts.json`.
- Отклонения фиксируются в `RUN_LOG` (формат `P2.2.1 deviation ...`).
- При BC-breaking изменениях партнёр обязан дать 30 дней notice.
