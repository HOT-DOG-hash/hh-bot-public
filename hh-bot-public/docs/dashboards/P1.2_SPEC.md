# P1.2 Team Dashboards – Observability Spec

## KPI Scope

### Operational KPIs

| KPI | Prometheus Metric | Labels | Primary Source | Notes |
| --- | --- | --- | --- | --- |
| Active auto-campaigns | `campaign_active_total` (gauge) | `mode` | `Campaign.status` aggregated via `hydrate_active_campaigns` + state transitions | Gauge hydrating on startup and adjusted on every start/pause/stop transition. |
| Auto-pauses triggered | `campaign_auto_pauses_total` (counter) | `reason` | `pause_campaign` service (`PauseRequest`) | Reason label aligns with auto remediation root cause. |
| Scheduler lag | `campaign_scheduler_lag_seconds` (gauge) | `partition` | Scheduler worker / `start_campaign` callback | Values in seconds; partitions allow sharded queue monitoring. |
| Delivery attempt errors | `delivery_attempt_errors_total` (counter) | `type` | Delivery worker error handler (`record_delivery_error`) | Type captures transport / partner error class. |
| Delivery outcomes | `campaign_delivery_logs_total` (counter) | `result` | Delivery log insertions (`CampaignDeliveryLog`) | Used to break down skips vs sent for context. |
| Operation latency | `campaign_operation_latency_seconds` (histogram) | `operation` | Service decorators (`track_operation_latency`) | Observability of API surfaces (start/stop/pause). |

### Growth & Billing KPIs

| KPI | Prometheus Metric | Labels | Primary Source | Notes |
| --- | --- | --- | --- | --- |
| Plan conversion | `payments_initiated_total`, `payments_succeeded_total` (counters) | `plan_code` | Billing service (`initiate_payment`, `process_webhook_event`) | Conversion = succeeded / initiated per plan. |
| Failed payments | `payments_failed_total` (counter) | `plan_code`, `reason` | Billing webhook handler | Distinguishes cancellations vs provider failures. |
| Revenue captured | `payments_revenue_minor_total` (counter) | `plan_code` | `process_webhook_event` on `PaymentStatus.SUCCEEDED` | Amount in minor currency units (RUB kopeks). |
| Refund volume | `payments_refunds_minor_total` (counter) | `plan_code` | Refund/chargeback events (future) | Metric present; remains `0` until refund integration lands. |
| Webhook processing lag | `webhook_lag_seconds` (histogram) | Prometheus buckets (`le`) | Billing webhook handler (occurred_at vs processed) | Bucketed in seconds; monitor long-tailed partner lag. |

## Metric Dictionary

### `campaign_active_total`
- **Type**: Gauge (`mode` label).
- **Source**: `hydrate_active_campaigns` query on startup + in-memory counters updated by `record_state_transition`.
- **Usage**: Primary KPI for live campaigns per targeting mode.

### `campaign_auto_pauses_total`
- **Type**: Counter (`reason`).
- **Source**: `pause_campaign` service when autopause reason recorded.
- **Usage**: Alerting on spikes by reason (cooldown breaches, quality guard-rails, etc.).

### `campaign_scheduler_lag_seconds`
- **Type**: Gauge (`partition`).
- **Source**: Scheduler worker and `start_campaign` post-action callback (`set_scheduler_lag`).
- **Usage**: Track backlog per scheduling shard; supports P99 SLA.

### `delivery_attempt_errors_total`
- **Type**: Counter (`type`).
- **Source**: Delivery worker wrapper (`record_delivery_error`).
- **Usage**: Break down partner/API vs transport failures, drives remediation playbooks.

### `campaign_delivery_logs_total`
- **Type**: Counter (`result`).
- **Source**: `CampaignDeliveryLog` writes (skip/failed/sent).
- **Usage**: Sanity check for throughput vs errors; complements pause/error KPIs.

### `campaign_state_transitions_total`
- **Type**: Counter (`from_state`, `to_state`).
- **Source**: `record_state_transition` in lifecycle operations.
- **Usage**: Audit stream for resume/pause/stop volumes; feeds run-rate charts.

### `campaign_operation_latency_seconds`
- **Type**: Histogram (`operation`).
- **Source**: Service decorator instrumentation.
- **Usage**: Backend latency guardrail for start/stop/pause operations.

### `campaign_idempotency_conflicts_total`
- **Type**: Counter (`endpoint`).
- **Source**: Idempotency guard rails when payload hash mismatches.
- **Usage**: Detect API mis-use or retrier bugs.

### `payments_initiated_total` / `payments_succeeded_total`
- **Type**: Counters (`plan_code`).
- **Source**: `initiate_payment` and `process_webhook_event`.
- **Usage**: Conversion funnel (initiated → succeeded) per plan.

### `payments_failed_total`
- **Type**: Counter (`plan_code`, `reason`).
- **Source**: `process_webhook_event` for terminal failure statuses.
- **Usage**: Monitor cancellations/expired vs technical failures.

### `payments_revenue_minor_total`
- **Type**: Counter (`plan_code`).
- **Source**: Successful webhook events, increments by `Plan.amount_minor`.
- **Usage**: Revenue dashboard; values are in minor currency units.

### `payments_refunds_minor_total`
- **Type**: Counter (`plan_code`).
- **Source**: Placeholder for refund/chargeback events (increments zero today).
- **Usage**: Keeps timeseries pre-created; highlight current gap.

### `webhook_lag_seconds`
- **Type**: Histogram (Prometheus buckets) + `sum`/`count`.
- **Source**: Billing webhook; difference between provider `occurred_at` and processing time.
- **Usage**: SLA on partner webhook latency (operational + billing).

### `daily_quota_remaining`
- **Type**: Gauge (`plan_code`).
- **Source**: Quota service updates (`set_daily_quota_remaining`).
- **Usage**: Support dashboard for quota consumption (secondary KPI).

## Data Sources & Refresh
- **`/metrics` endpoint** (`backend/app/routers/metrics.py`): Prometheus scrape target outputting all counters/gauges/histograms above.
- **Campaign lifecycle events**: Writes into `Campaign`, `CampaignDeliveryLog`, `CampaignAuditLog` via `backend.app.services.auto_campaigns`.
- **Billing events**: Payment initiation + YooMoney webhook pipeline (`backend.app.services.billing`).
- **Hydration hook**: `startup_ping` now hydrates `campaign_active_total` using a DB snapshot to avoid cold-start drift.

## Known Gaps / Follow-ups
- `payments_refunds_minor_total` stays at `0` until refund/chargeback events are wired in (documented for Grafana backlog).
- Delivery worker must emit `record_delivery_error` for every failure mode; current scope covers timeout example only.
- Ensure scheduler periodically refreshes `campaign_scheduler_lag_seconds` for all partitions once queue sharding is introduced.
